# M2c RTSP Ingest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pull RTSP (TCP interleaved and UDP) from cameras and servers through our own `pkg/rtsp` client, derive DTS for RTP video (which carries PTS only) with our own `pkg/h26x`, and use the same `pkg/h26x` to recover the reordered access units the TS demuxer drops today — completing M2.

**Architecture:** `pkg/h26x` parses the H.264/H.265 parameter-set and slice-header fields it needs with its own bounded bit reader, computes picture order counts, and derives DTS from presentation order and the reorder depth. `pkg/rtsp` is a reusable library with no `internal/` imports: RTSP message codec, Basic and Digest authentication, SDP via `pion/sdp`, our own H.264/H.265/RFC 3640 depacketisers (and the RFC 3640 packetiser M3b reuses), RTCP sender/receiver reports, a client session over TCP interleaved or UDP, and `pkg/rtsp/rtsptest` (a scripted server for tests). `internal/ingest` adds an RTSP pull input that turns RTP access units into `media.Frame`s on one timeline.

**Tech Stack:** Go (`go 1.26.11`); `pion/rtp` (latest v1.x: `rtp.Packet` parsing everywhere; its `codecs` H.264/H.265 payloaders only in tests and `rtsptest`) and `pion/sdp/v3` (latest v3.x), both approved in REBUILD_PLAN §3.7; `Eyevinn/mp4ff` v0.52.0 stays only where it is used today (`internal/media`), behind a new pre-check; standard library; `stretchr/testify`. Test peers: MediaMTX (RTSP, fed by ffmpeg), ffprobe for reference DTS.

**Spec:** [docs/REBUILD_PLAN.md](../../REBUILD_PLAN.md) §2 (Inputs: RTSP pull), §3.1, §3.2, §3.7 (`pkg/h26x`, `pkg/rtsp`, `pion/rtp`, `pion/sdp`), the M2 and M2c rows of §5, the §6 risk on `pkg/h26x` DTS (checked against ffmpeg's DTS), and the M2a ruling that reordered access units packed in one PES wait for `pkg/h26x`. References: RFC 2326 (RTSP 1.0), RFC 7617/7616/2069 (Basic/Digest), RFC 8866 (SDP), RFC 3550 (RTP/RTCP), RFC 6184 (H.264 payload), RFC 7798 (H.265 payload), RFC 3640 (AAC), ITU-T H.264 §7.3/§8.2.1 and H.265 §7.3/§8.3.1 — never another product's code. M3b adds the RTSP server on the same library.

**M2c exit criteria** (the M2 row restricted to M2c): our RTSP client interoperates with MediaMTX over TCP and UDP; RTSP inputs fed by MediaMTX (published by ffmpeg) produce violation-free frames for H.264 with B-pyramids, H.265 open GOP and AAC; failover between an RTSP input and another input is exactly one epoch change; `pkg/h26x` DTS equals ffmpeg's DTS minus one constant on the B-frame, B-pyramid and H.265 fixtures; the TS demuxer recovers reordered access units packed in one PES when POC is available.

**Out of M2c, with reasons** (ledger rulings at dispatch): RTSP 2.0, RTSPS/SRTP (TLS is M5 like RTMPS; `rtsps://` is rejected with a clear error); UDP multicast transport and RTSP-over-HTTP tunnelling (rare for pull); MP4A-LATM, G.711, Opus, PCM (§2 codec scope; such tracks are skipped with a reason); H.264 packetization-mode 2 and H.265 with `sprop-max-don-diff > 0` (interleaved, DON reordering; skipped with a reason); credentials in the URL path or query (Xiongmai-style `?user=&password=`; noted for M5 redaction work); the RTSP server (M3b); ONVIF.

## Global Constraints

- Every Global Constraint of the M1, M3a, M2a and M2b plans still holds (independent libraries; `pkg/...` never imports `internal/...`; errors `pkg: op: %w`; never log and return the same error; goroutines have cancel paths; readers emit source time with arrival stamps and `Epoch` zero; `ErrDiscontinuity` once per break; the Open ctx bounds only the open; Config pointers stable via `media.ConfigCache`; peer tests via `internal/testpeer`; URLs and credentials redacted).
- New module dependencies: `github.com/pion/rtp`, `github.com/pion/sdp/v3` and whatever they pull transitively (e.g. `pion/randutil`); versions recorded in the commit that adds them.
- **Ownership:** every slice returned by `pkg/rtsp` and `pkg/h26x` is a fresh allocation owned by the caller.
- **Hostile bitstreams (`pkg/h26x`):** exp-Golomb codes with more than 31 leading zeros fail; every count read from a bitstream is checked against its spec range before any loop or allocation (e.g. `num_ref_frames_in_pic_order_cnt_cycle` ≤ 255, `num_short_term_ref_pic_sets` ≤ 64, `num_ref_idx_active_minus1` ≤ 31); a parse failure returns an error, never panics.
- **Bounds (`pkg/rtsp`, fields of `rtsp.Config` and `rtsp.Limits`, defaults when zero):** dial and each request/response ≤ 10 s; response or request header block ≤ 64 KiB; body ≤ 1 MiB; RTP packet ≤ 64 KiB; one access unit ≤ 8 MiB (larger dropped, counted); UDP reorder buffer ≤ 64 packets or 200 ms per track; UDP packet channel 1024 packets (drop newest when full, counted); at most 16 media in an SDP (extra skipped); keepalive at half the server's session timeout (default timeout 60 s); RTCP receiver report every 5 s per track; no packet at all on any track for `IdleTimeout` (default 10 s) → error.
- **Timing:** RTP timestamps unwrapped per track with `pkg/unwrap` (32 bits); sequence numbers unwrapped at 16 bits, a jump > 3000 or an SSRC change is a reset (counted), not a loss. Video clock must be 90000 (else the track is skipped with a reason). Audio PTS in 90 kHz from the unwrapped RTP timestamp at the RTP clock rate: `floor(ts·90000/clockRate)` (for HE-AAC sent at the SBR clock this is the SBR rate, not the ASC core rate). **Alignment:** each track gets an offset that maps its RTP time onto the reference track (video, else the first track). A provisional offset comes from the PLAY response's `RTP-Info` (`rtptime` of every track marks the same instant) or, when missing, from the arrival time of each track's first packet (counted `sync_by_arrival`). The first RTCP sender report pair for a track gives its SR offset (NTP of RTP ts T = `SR.ntp + (T − SR.rtp)/clock`): if it differs from the provisional offset by ≤ 50 ms the provisional offset is kept, otherwise it replaces it with one `ErrDiscontinuity` (counted `sync_corrected`). After that the offset changes only when a later SR implies a move > 100 ms (`ErrDiscontinuity`, counted `sync_jumps`); smaller drift is ignored. An SSRC change or an RTP timestamp jump > 10 s on a track → its SR state is dropped and it re-aligns provisionally by arrival with `ErrDiscontinuity` (a later SR then corrects it by the rules above). `Open` waits for SRs on every track up to `SyncWait` (default 1 s) before emitting frames.
- **Video AU assembly:** per track by RTP timestamp only: an AU ends when a packet with a different timestamp arrives (or at `Flush`); the marker bit is ignored, because cameras set it per slice or on parameter sets (cost: one frame interval of latency); an AU without a slice (SPS/PPS/SEI sent alone) is carried into the next AU. NAL units without start codes; parameter sets from SDP `sprop-*` and in-band moved into `Config`; AUD dropped; `Key`/`RASL` from `media.NALClassifier`; DTS from `h26x.DTSExtractor`. A sequence gap inside an AU drops that AU (`lost_aus`); when the packet revealing the gap carries a new timestamp, both the pending AU and the AU it starts are marked Lost (the missing packets may be the tail of one or the head of the other); frames after it pass through (the M2a loss ruling) — loss never resets the DTS extractor.
- **Credentials:** `pkg/rtsp` strips userinfo from the URL in `Dial` and from every URL it derives (Content-Base, control URLs) before sending or storing it; `Authorization`, the password and Digest responses never appear in errors or logs; `ingest.Redact` masks the input URL as today.
- Input URL schemes (added to `ingest.Parse`/`Open`; port defaults to 554):

| URL | Input | Spec |
|---|---|---|
| `rtsp://[user:pass@]host[:port]/path[?q]` | RTSP pull; `?transport=tcp` (default), `udp`, or `auto` (UDP, falling back to TCP when no RTP arrives within 3 s); our `transport` parameter is removed before the URL is sent | Live |
| `rtsps://…` | rejected: "rtsps is not supported" | — |

### Task 4: `pkg/h26x` DTS extractor

**Files:** Create `pkg/h26x/dts.go`; Test `pkg/h26x/dts_test.go`

**Interfaces — produces:**

```go
type DTSExtractor struct{ /* reorder depth R, min-heap of pending PTS, lastDTS, frame duration, started */ }
type DTSStatus uint8 // DTSOK, DTSDrop, DTSBreak
func NewDTSExtractor(reorder int, frameDuration int64) *DTSExtractor // reorder from h26x.ReorderOf, clamped to [0,16]
// Extract returns the DTS for the next access unit in decode order. DTSDrop: drop the frame (before the first keyframe,
// a leading picture of the first keyframe, or a late frame). DTSBreak: the PTS jumped backwards past the window — the
// extractor has reset itself and the caller emits ErrDiscontinuity (the frame is then handled as after Reset).
func (d *DTSExtractor) Extract(pts int64, key bool) (dts int64, st DTSStatus)
func (d *DTSExtractor) Reset()           // timeline break (new SSRC, timestamp jump): next keyframe starts again
func (d *DTSExtractor) SetReorder(r int) // a new SPS: a higher R applies at once, a lower R at the next Reset
func (d *DTSExtractor) Stats() DTSStats  // Leading, Late, Breaks, ReorderRaised uint64
```

R comes from `ReorderOf` (callers count `reorder_assumed`). Algorithm (our own): with R frames of reorder, the decode index of a frame is at most its display index + R, so the DTS of the k-th decoded frame is the PTS of display frame k−R. Keep a min-heap of pending PTS across GOPs: push each PTS; when the heap holds more than R, pop the minimum as the DTS. For the first R frames after start or `Reset`, DTS = max(lastDTS+1, min(heap) − (R − k)·duration), with duration fixed at the window's first frame: `frameDuration` if known, else 3000 (any positive value keeps DTS valid; lastDTS+1 ≤ min(heap) ≤ PTS always holds). After start or `Reset`, frames before the first keyframe and frames with PTS below the first keyframe's PTS are dropped (`Leading`). A PTS more than max(90000, (R+2)·duration) below the last DTS → `DTSBreak` (`Breaks`). A smaller PTS below the last DTS (R underestimated) → frame dropped (`Late`) and R += 1 (max 16) at most once per episode (no further raise until a DTS has been emitted, `ReorderRaised`); whenever the heap holds ≤ R entries after the start window (after a raise, or after `SetReorder` raised R), DTS = lastDTS+1. `Reset` and `DTSBreak` clear lastDTS, so a new window has no lower bound from the old timeline. DTS is never clamped above its PTS.

### Task 5: Reordered access units in one PES (TS demuxer)

**Files:** Modify `internal/ts/demux.go`; Test `internal/ts/broadcast_test.go`

Replaces the M2a drop rule. Each H.264/H.265 track gets a lazily created `h26x.POCCounter`, started at the first PES that holds more than one AU (then fed every AU of the track in decode order from `finishAU`; ok=false until its first reference picture — split AUs before that are dropped as today). For a PES with several AUs and POC available (whatever `ptsIsDTS` says): the first AU keeps the PES PTS/DTS; ticks per POC unit are calibrated as the fraction ΔPTS/ΔPOC between the first AUs of two PES in the same POC period (kept as a numerator/denominator pair, never truncated; until calibrated, split AUs are dropped as today); a later AU gets PTS = firstPTS + (POC − firstPOC)·ΔPTS/ΔPOC, rounded once; DTS spaced as today. A POC reset inside the group drops the rest of the group (counted); a computed PTS below its DTS drops that AU. Counter `split_aus_poc`; `SplitAUsReordered` keeps counting drops. Cost: slice-header parsing runs only on tracks that have produced a multi-AU PES.
