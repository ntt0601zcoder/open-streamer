# M2b RTMP Ingest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ingest RTMP push (encoders publishing to us) and RTMP pull (us playing from a server) through our own `pkg/rtmp` and `pkg/unwrap`, so that ffmpeg and MediaMTX interoperate with our library as peers and every RTMP input yields violation-free frames through the existing pipeline, failover included.

**Architecture:** `pkg/unwrap` unwraps N-bit timestamps. `pkg/rtmp` is a reusable library with no `internal/` imports: AMF0, the handshake (simple and digest), the chunk stream, FLV tag parsing and building (legacy AVC/AAC and enhanced RTMP for H.265/AVC FourCC), a session core (control messages, acknowledgements, pings, timeouts, aggregates), a server publish flow and a client play flow, plus `pkg/rtmp/rtmptest` (a reusable publisher and scripted play server for tests in other packages). `internal/ingest` turns FLV tags into `media.Frame`s and adds two inputs: an RTMP listener whose TCP port is shared by every stream on that address (routed by path), and an RTMP pull client. Both plug into the M2a pipeline unchanged.

**Tech Stack:** Go (`go 1.26.11`), `Eyevinn/mp4ff` v0.52.0 (AVC/HEVC decoder configuration records, ASC), standard library (`net`, `bufio`, `crypto/hmac`, `crypto/sha256`), `stretchr/testify`. Test peers: ffmpeg (RTMP publish, `-listen 1` server, enhanced-FLV HEVC muxing where supported) and MediaMTX (docker image as a CI service, never a dependency).

**Spec:** [docs/REBUILD_PLAN.md](../../REBUILD_PLAN.md) §2 (Inputs: RTMP push and pull), §3.1, §3.2, §3.7 (`pkg/unwrap`, `pkg/rtmp`), the M2 row and the M2b row of §5. References: Adobe RTMP specification 1.0 (2012), FLV specification v10.1, Enhanced RTMP (Veovera, v1 FourCC video and v2 ModEx) — never another product's code. M3b will add server play and client publish on the same session core.

**M2b exit criteria** (the M2 row restricted to M2b): our RTMP library interoperates with ffmpeg and MediaMTX as peers (we accept ffmpeg's publish; we pull from ffmpeg and from MediaMTX); each RTMP input fed by them produces violation-free frames; failover between an RTMP input and an M2a input is exactly one epoch change; H.265 over enhanced RTMP works end to end with an independent writer (an ffmpeg-made enhanced-FLV fixture and MediaMTX).

**Out of M2b, with reasons** (ledger rulings at dispatch): RTMPS/TLS (certificates and config, M5); RTMPT/RTMPE (obsolete); Enhanced RTMP v2 multitrack and non-H.26x/AAC codecs (AV1, VP9, Opus, MP3 — §2 scope); AMF3 command encoding (clients requesting objectEncoding 3 are rejected); publish authentication beyond an exact path match (M6 sessions/tokens); server play and client publish (M3b).

## Global Constraints

- Every Global Constraint of the M1, M3a and M2a plans still holds (independent libraries; `pkg/...` never imports `internal/...`; errors `pkg: op: %w`; never log and return the same error; goroutines have cancel paths; readers emit source time with arrival stamps and `Epoch` zero; `ErrDiscontinuity` once per break; the Open ctx bounds only the open; Config pointers stable via `media.ConfigCache`; peer tests via `internal/testpeer`; URLs redacted).
- No new module dependency. The handshake digest keys (the public Genuine Adobe Flash Player/Media Server constants) are data.
- **Ownership:** every `Payload`/`Data` slice returned by `pkg/rtmp` (messages, media, tags) is a fresh allocation owned by the caller; nothing is reused or aliased across calls.
- **Bounds for an internet-facing listener** (all in `rtmp.Config`, defaults when zero): handshake ≤ 5 s; connect/publish command exchange ≤ 10 s; until `publish` is accepted a server allows messages ≤ 64 KiB, ≤ 8 chunk streams and ≤ 256 KiB of partially assembled bytes per connection; after it (and for clients) messages ≤ 8 MiB, ≤ 64 chunk streams and ≤ 16 MiB partial bytes (buffers grow as data arrives, never pre-allocated from the declared length); a peer's Window Ack Size clamped to ≥ 4096; inbound Set Chunk Size: 0 or MSB set → error, values > 0xFFFFFF clamped to 0xFFFFFF; AMF0 depth ≤ 16, string ≤ 1 MiB, ≤ 4096 values; listener policy (in `internal/ingest`, passed to `register`): at most 64 sessions that have not yet published and at most 4 per remote IP (an IPv6 peer counted by its /64) (excess closed right after accept, counted).
- **Session defaults:** we send Set Chunk Size 4096, Window Ack Size 2 500 000, Set Peer Bandwidth 2 500 000 (dynamic); ping (PingRequest) every 10 s; a session with no inbound byte for 30 s fails.
- **Timestamps:** RTMP message timestamps are 32-bit milliseconds, unwrapped per session with `pkg/unwrap` (32 bits), source time = ms × 90 exactly. Aggregate sub-message timestamp = aggregate timestamp + (sub.ts − firstSub.ts) mod 2^32. RTMP inputs deliver per message, so `Spec.ArrivalGranularity` is 0 (pull-side aggregates of ≤ 1 s still leave ≥ 3 arrivals per 10 s drift window).
- **Video timing:** PTS = DTS + composition offset (signed 24-bit ms) × 90. Negative offsets are absorbed by a per-session DTS shift `s` that only grows: `DTS' = DTS − s`. The initial `s` is learned by `flvFrames` itself, per session (so also after a reconnect, a takeover and on pull): video frames are held from the first video frame until the second keyframe or 1 s of source time, whichever comes first; `s = max(0, −min CTS)` over the held frames; then they are released in order (audio is not held; the Clock aligns tracks). This adds at most 1 s of start-up latency to video. After that, when a frame has `CTS < −s`, set `s = −CTS` and clamp `DTS' = max(DTS', prevDTS' + 1)` (the rare late increase may then cost that one frame, counted as `dts_shift_late`); PTS stays exact; shifts are counted (`dts_shifts`). With the canonical I P B B pattern no frame ends with PTS < DTS.
- **Audio timing:** frames are placed on the sample grid at the ASC core rate (`TrackConfig.SampleRate`): `PTS_k = anchor + floor(k·1024·90000/rate)`. With `d` = one frame and `dev = rtmpTime − gridTime`: `|dev| ≤ d` → stay on the grid; `dev > d` → re-anchor forward (a gap; `audio_reanchors`); `−1 s < dev < −d` → drop that frame (`audio_dropped_ahead`); `|dev| ≥ 1 s` → re-anchor (encoder reset; the Clock handles the jump). A dropped frame does not advance `k`.
- **Video data:** NAL units without start codes, length size from the decoder configuration record (`lengthSizeMinusOne + 1`), parameter sets moved into `Config` (from the record and in-band), non-parameter-set NALs in record arrays ignored, AUD dropped; `Key`/`RASL` from `media.NALClassifier`.
- **Redaction:** for `rtmp://` URLs `ingest.Redact` masks the stream name (last path segment) keeping its first 2 characters, plus the existing userinfo/query rules; rejection messages never echo the requested name; "unknown" and "busy" keys get the same `NetStream.Publish.BadName` description ("stream not available").
- Input URL schemes (added to `ingest.Parse`/`Open`; port defaults to 1935; `mode` accepts `listen` and `listener` as synonyms and `pull`; our `mode` parameter is stripped before the query is sent to a server):

| URL | Input | Spec |
|---|---|---|
| `rtmp://host[:port]/app[/…]/stream[?q]` (`mode` defaults to `pull` when a host is given) | RTMP pull (play) | Live |
| `rtmp://[:port]/app[/…]/stream?mode=listen` (empty host, `0.0.0.0` or `[::]`, all the same address) | RTMP listen for exactly this path; one TCP listener per port shared by every listen input on it | Live, Passive |

### Task 3: `pkg/rtmp` handshake

**Files:** Create `pkg/rtmp/handshake.go`; Test `pkg/rtmp/handshake_test.go`

**Interfaces — produces:**

```go
func ServerHandshake(rw io.ReadWriter, rand io.Reader) error // reads exactly C0+C1 and C2 with io.ReadFull; never reads past C2

```

Server: C0 version must be 3. If C1 carries a valid digest (schema 0 or schema 1 offsets, HMAC-SHA256 with the first 30 bytes of the client key "Genuine Adobe Flash Player 001"), answer a digest S1 in the same schema with a non-zero version field (0x0D0E0A0D) signed with the first 36 bytes of "Genuine Adobe Flash Media Server 001", and S2 signed with HMAC(key = HMAC-SHA256(full 68-byte FMS key, C1 digest)); otherwise answer the simple handshake (S1 random with zero version, S2 = C1 echo). C2's content is read and not validated. Client: send a digest C1 (schema 1, version 0x80000702); verify S2 only when S1 carries a valid digest (mismatch → error). Deadlines belong to the caller. The session wraps the conn in one `bufio.Reader` that both the handshake and the chunk reader use, so bytes sent right after C2 (the `connect` chunk in the same segment) are never lost.

Timestamp rules (pin each in tests): fmt 0 carries an absolute timestamp and resets the chunk stream's delta to 0; fmt 1/2 carry a delta; a fmt 3 chunk that starts a new message adds the stream's last delta (0 after fmt 0); the extended timestamp is present when the 24-bit field (absolute for fmt 0, delta for fmt 1/2) equals 0xFFFFFF, and on fmt 3 chunks of such a message. ```

Counters (per listener): `rejected_unknown`, `rejected_busy`, `rejected_flood`.
