# M3a HLS, DASH and HTTP-TS Outputs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the M1 media core as live HLS (TS and fMP4), DASH and HTTP-TS, playable in ffplay/VLC/hls.js/dash.js, prove every output correct with a conformance reader (`osconform`), and replace go-astits with our own MPEG-TS layer.

**Architecture:** `pkg/mpegts` gains a TS packet reader that resynchronises, PSI and PES assembly, and a TS writer; `internal/ts` moves onto it and go-astits leaves the module. A pipeline feeds a TS source through demuxer → Clock → hub and registers each epoch's wallclock anchor on the hub. One packager per stream subscribes to the hub, cuts segments on keyframes (one segmenter for every format), muxes each segment as TS and as per-track CMAF fMP4, and keeps a sliding window. HTTP handlers build the HLS playlists and the DASH MPD from that window on request. HTTP-TS streams frames straight from the hub. The conformance reader fetches every output over HTTP, turns it back into frames, and runs the M1 frame checks plus container checks.

**Tech Stack:** Go (`go 1.26.10` in `go.mod`), `Eyevinn/mp4ff` v0.52.0, `net/http` and `encoding/xml` from the standard library, our own CRC-32/MPEG-2 (non-reflected, so not `hash/crc32`'s IEEE table), `stretchr/testify`. ffprobe/ffplay as the independent oracle for TS and fMP4, and for manual checks.

**Spec:** [docs/REBUILD_PLAN.md](../../REBUILD_PLAN.md) §3.3, §3.4, §3.7 (including the `pkg/mpegts` row) and the M3 row of §5. M3a is the part of M3 that needs no M2 library. RTMP play, RTMP push, RTSP and SRT outputs come in M3b after M2. Low-latency parts are deferred. §3.4's "epoch helper" is realised as the packager's discontinuity, period and init rules (Tasks 13–16).

## Global Constraints

- Every Global Constraint of the M1 plan still holds, except that goroutines are allowed in `internal/pipeline`, `internal/output/...` and `cmd/...`. Each goroutine stops when its `context.Context` is cancelled; tests verify that under `-race`.
- Module dependencies: the standard library, `Eyevinn/mp4ff`, `stretchr/testify`. go-astits is allowed only until Task 7 removes it. No HTTP framework: `net/http` `ServeMux` patterns.
- Only independent libraries; never `bluenviron/*` or `q191201771/lal`, and never copy their code (nor go-astits'). `pkg/...` never imports `internal/...`.
- Outputs never use wallclock for media timing; media timing comes only from frame PTS/DTS. Wallclock appears only in HLS `EXT-X-PROGRAM-DATE-TIME`, DASH period placement and segment availability, always through epoch anchors and the packager's `Now`.
- Parameter sets live only in `TrackConfig`. The TS muxer inserts all of them before every keyframe; the fMP4 writer puts them in the init segment.
- Every TS the system writes carries PTS/DTS of stream time + 126000 ticks (1.4 s) and a PCR of stream DTS + 63000 (0.7 s of decoder buffer), all modulo 2^33, so the PCR is never negative, including after the wrap.
- Defaults: segment target 2 s (180000 ticks); live window 6 segments; DASH `minimumUpdatePeriod` = target, `timeShiftBufferDepth` = window × target, `suggestedPresentationDelay` = 3 × target, `minBufferTime` = target.
- URL layout under `/live/{stream}/`:

| Path | Content |
|---|---|
| `hls/index.m3u8`, `hls/{seq}.ts` | HLS, muxed TS segments |
| `cmaf/master.m3u8`, `cmaf/v{track}.m3u8`, `cmaf/a{track}.m3u8` | HLS, fMP4 segments |
| `cmaf/index.mpd` | DASH |
| `cmaf/init-{track}-{epoch}.mp4`, `cmaf/{track}-{n}.m4s` | CMAF init and media segments, shared by HLS-fMP4 and DASH; `n` counts that track's segments from 0, so DASH `$Number$` has no holes |
| `stream.ts` | Continuous HTTP-TS |

### Task 4: `pkg/mpegts` packet reader

**Files:** Create `pkg/mpegts/packet.go`, `pkg/mpegts/reader.go`; Test `pkg/mpegts/reader_test.go`

**Interfaces — produces:**

```go
const PacketSize = 188
type Packet struct {
    PID           uint16
    PUSI          bool  // payload_unit_start_indicator
    CC            uint8
    HasPayload    bool
    Discontinuity bool  // adaptation field discontinuity_indicator
    RandomAccess  bool  // adaptation field random_access_indicator
    PCR           int64 // PCR base (90 kHz, 33 bits); -1 when absent
    Payload       []byte // valid until the next Next call
}
func NewReader(r io.Reader) *Reader
func (r *Reader) Next() (Packet, error) // io.EOF at the end; a trailing partial packet is dropped
func (r *Reader) Stats() ReaderStats
type ReaderStats struct { Packets, Resyncs, SkippedBytes, Errored uint64 }
```

Rules:
- Works with any `io.Reader`, including one that returns one byte per call; no seeking.
- Lock: at the start, and whenever the byte at the next expected packet start is not 0x47, scan forward for an offset `o` where bytes `o`, `o+188` and `o+376` are all 0x47; a position counts as matching when the underlying reader has returned EOF before it (not merely when it is not buffered yet). Bytes skipped are counted in `SkippedBytes`; each scan that skips bytes counts one `Resync`.
- Known limitation (documented on the type): when bytes go missing inside a packet, that packet is emitted with the next packet's first bytes and the next packet is lost; the demuxer's continuity check catches it when both are on one PID. 192- and 204-byte packets are out of scope.
- A non-EOF read error is returned as is.
- A packet with `transport_error_indicator` set, or an adaptation field length that does not fit, is dropped and counted in `Errored`.

### Task 5: `pkg/mpegts` PSI and PES demultiplexing

**Files:** Create `pkg/mpegts/psi.go`, `pkg/mpegts/crc.go`, `pkg/mpegts/demux.go`; Test `pkg/mpegts/demux_test.go`

**Interfaces — consumes** Task 4; **produces:**

```go
type Stream struct { PID uint16; Type uint8 }
type PMT struct { Program, PID uint16; Version uint8; PCRPID uint16; Streams []Stream }
type PES struct {
    PID           uint16
    PTS, DTS      int64 // raw 33-bit; DTS == PTS when the header has no DTS
    HasPTS        bool
    RandomAccess  bool  // from the PES's first packet
    Discontinuity bool  // data on this PID was lost before this PES
    Data          []byte // owned by the caller
}
type Event struct { PMT *PMT; PES *PES } // exactly one is set
func NewDemux(r io.Reader) *Demux
func (d *Demux) Next() (Event, error) // io.EOF after pending PES are flushed; read errors are returned, decoding errors only counted
func (d *Demux) Stats() DemuxStats
type DemuxStats struct { Reader ReaderStats; CCErrors, PSIErrors, PESErrors uint64 }
```

Rules:
- **PSI:** the first program in the PAT with a non-zero program number (program 0, the network PID, is skipped). Sections are reassembled across packets using the pointer field, and several sections may follow in one payload until a 0xFF byte. CRC-32/MPEG-2 is checked; a bad CRC or malformed section counts in `PSIErrors` and is ignored. Sections with `current_next_indicator` 0 and other `table_id`s on the PAT or PMT PID are ignored without error. A PAT that changes the PMT PID resets PMT state, so the next PMT counts as a change.
- **PMT events:** returned for the first PMT and whenever its version, PCR PID or stream list changes; repetitions return nothing.
- **PES assembly** only for PIDs in the current PMT. A PES completes when its `PES_packet_length` is non-zero and that many bytes have arrived (returned at once); a length-0 PES completes at the next PUSI on its PID or at EOF. A sized PES still incomplete at the next PUSI or at EOF is dropped and counted in `PESErrors`. At EOF, pending PES are flushed in ascending PID order. A PES whose start was never seen is ignored.
- **Continuity** is tracked only for PID 0, the PMT PID and the PMT's elementary-stream PIDs (never 0x1FFF). A packet without payload repeats the previous CC and does not advance it; one whose CC differs from the previous one counts as a gap, and its CC becomes the new reference. A packet with payload and the same CC as the previous one is a duplicate and ignored. The CC check runs before PUSI handling: a CC gap drops the PES (or PSI section) in progress on that PID, even when the gap packet has PUSI set, counts one `CCErrors`, and marks the next PES `Discontinuity`. A packet whose adaptation field sets `discontinuity_indicator` resets CC tracking without an error.
- A PID removed from the PMT, or whose stream type changes: a pending length-0 PES is flushed and returned before the PMT event; a sized incomplete one is dropped and counted. A removed PID is ignored, and its CC state cleared, until a PMT lists it again. A PAT that changes the PMT PID clears every pending PES, the PMT's PID set, and the CC state of the old PMT PID and its ES PIDs: pending length-0 PES are flushed first, sized incomplete ones are dropped and counted in `PESErrors`.
- A PES header that cannot be parsed counts in `PESErrors` and is dropped.

### Task 8: Segmenter

**Files:** Create `internal/segment/segmenter.go`; Test `internal/segment/segmenter_test.go`

**Interfaces — consumes** `hub.Delivery`; **produces:**

```go
type Options struct { Target int64 } // 0 means 180000
type Segment struct {
    Seq           uint64        // from 0, never reused
    Epoch         uint32
    Discontinuity bool          // first segment after an epoch change or Lost > 0
    Start         int64         // PTS of the anchor track's first frame
    Duration      int64         // ticks, anchor track
    End           int64         // largest frame PTS + that track's last DTS delta within the segment, over all tracks
    Frames        []media.Frame // arrival order, all tracks
}
func New(opt Options) *Segmenter
func (s *Segmenter) Push(d hub.Delivery) []Segment
func (s *Segmenter) Flush() []Segment
func (s *Segmenter) Dropped() uint64
```

Rules:
1. An epoch's anchor track is its lowest-numbered video track, else its lowest-numbered audio track.
2. A segment opens on an anchor-track keyframe (any anchor frame for audio). A frame that arrives with no open segment and cannot open one is dropped and counted.
3. An open segment closes before a delivery with a different `Epoch` or `Lost > 0`; the next segment has `Discontinuity = true`. The first segment ever has `Discontinuity = false`.
4. Otherwise it closes when an anchor keyframe (any anchor frame for audio) arrives with PTS ≥ `Start + Target`.
5. `Duration` = `next.Start − Start` when closed by rule 4; otherwise (rule 3 or `Flush`) the largest anchor PTS in the segment + the anchor track's last DTS delta within the segment (3600 if it has one frame) − `Start`. `End` uses the same per-track delta rule (audio: `SampleTime(1024, rate)`).
6. In a segment opened after `Lost > 0`, non-anchor frames with PTS below `Start` are dropped and counted.

### Task 9: CMAF fMP4 writer

**Files:** Create `internal/mux/fmp4/fmp4.go`; Test `internal/mux/fmp4/fmp4_test.go`

**Interfaces — produces:**

```go
func Timescale(c *media.TrackConfig) uint32 // 90000 for video, SampleRate for audio
func Init(c *media.TrackConfig) ([]byte, error)                                 // single track, track ID 1
func Segment(frames []media.Frame, c *media.TrackConfig, seq uint32) ([]byte, Timing, error) // one track, decode order; empty input is an error
type Timing struct { BaseTime, Earliest, Duration uint64 }                       // Timescale units
```

Rules:
- Video: `CreateEmptyInit`, `AddEmptyTrack(90000, "video", "und")`, then `SetAVCDescriptor("avc1", SPS, PPS, true)` or `SetHEVCDescriptor("hvc1", VPS, SPS, PPS, nil, true)`. Samples are 4-byte length-prefixed NAL units; decode time = DTS; duration = next DTS − DTS, the last repeating the previous (3600 if alone); composition offset = PTS − DTS (trun version 1); sync flag from `Key`.
- Audio: `AddEmptyTrack(rate, "audio", "und")`, then add `CreateAudioSampleEntryBox("mp4a", channels, 16, rate, CreateEsdsBox(ASC))` with `Stsd.AddChild`, because `SetAACDescriptor` hard-codes 2 channels. Sample rates above 65535 are an error. Decode time = `Rescale(DTS, rate)`; a sample lasts `Rescale(nextDTS − DTS, rate)`, the last one 1024, so contiguous audio always lasts 1024 and a gap in the input stays a gap in the timeline. A segment's `tfdt` may differ by ±1 from the previous segment's base + duration; no rule checks that.
- `Timing.BaseTime` = first decode time (`tfdt`); `Timing.Earliest` = the smallest decode time + composition offset over the segment's samples (the earliest presentation time); `Timing.Duration` = sum of sample durations.

### Task 13: Packager, window and file serving

**Files:** Create `internal/output/live/packager.go`, `store.go`, `http.go`; Test `internal/output/live/packager_test.go`

**Interfaces — consumes** Tasks 1, 8, 9, 10; **produces:**

```go
type Options struct { Target int64; Window int; Now func() time.Time } // Window 0 means 6; Now nil means time.Now
func NewPackager(h *hub.Hub, opt Options) *Packager
func (p *Packager) Handle(d hub.Delivery)                 // synchronous
func (p *Packager) Flush()

```

Rules:
- Each closed segment is muxed once as TS and once per track that has frames in it as CMAF. TS uses one `ts.Muxer` per packager, retargeted with `SetOutput` to a fresh buffer per segment and `SetTracks` to the segment's tracks, with tables written first. A track with no frames in a segment gets no CMAF segment. An init is written per (track, epoch) when the track first has frames in that epoch.
- **Effective epoch wall.** When an epoch's first segment is packaged, the packager computes and stores its period start once, rounded up to the millisecond: AST = wall of the first anchor ever seen (fixed); `start_1 = anchor_1.Wall − AST`; `start_n = max(anchor_n.Wall − AST, start_{n−1} + (anchor_n.Start − anchor_{n−1}.Start)/90000 s)`. - The window keeps the last `Window` segments. A segment is *listed* (in every playlist and the MPD alike) once `W_n + (End − anchor_n.Start)/90000 s ≤ Now`, so no listed media of any track lies in the future.
- A mux error drops that segment's output in that format and increments `Errors()`; it never stops the packager.
- 404 for an unknown stream or file, an out-of-window segment, and every playlist before the first listed segment.
